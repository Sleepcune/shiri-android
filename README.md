# 拾日（Shiri）

拾日是一个离线优先的 Android 个人生活助手：把记账、课表、待办和饮食记录放在同一个本地数据模型中，并通过可选的 OpenAI-compatible API 提供对话、课表导入和日报能力。

> 当前源码对应 Android 应用，不是 Windows 桌面应用。底层应用标识仍为 `com.hubra.app`，用于保持已安装版本、通知和本地数据的升级兼容性。

## 已实现功能

- **记账**：消费、收入、转账、退款、调整，金额使用整数分保存；支持账户初始化、核账和操作记录撤销。
- **课表**：学期、周次、节次、课程规则、停课/调课/补课和待补全课程；支持课前提醒与桌面组件。
- **待办**：一次性和重复待办、单次延期、完成/恢复、课程关联；通知支持直接完成当次待办。
- **饮食与图片**：餐食记录、图库图片、OCR/饮食分析；图片保存在应用私有目录，可加密备份和导出。
- **AI 能力**：多个独立 API 配置、模型能力检测、结构化操作白名单、可取消请求和本地执行结果校验。
- **提醒诊断**：AlarmManager 调度、重启/时钟/时区/权限变化后的重排、过期检查、投递状态和失败原因记录。
- **数据保护**：Room 聚合状态、版本化迁移、Keystore 加密 API Key、加密备份、附件删除保护。

## 系统要求

- Android 8.0（API 26）或更高版本。
- 构建目标为 Android API 35，Java 17，Kotlin 2.1.20。
- 需要通知权限时，Android 13 及以上还需授予 `POST_NOTIFICATIONS`。
- 精确提醒权限可能由系统单独控制；关闭后会降级为系统允许时触发的非精确提醒。

本项目不是 Windows 原生桌面应用，不承诺 Windows、iOS 或其他平台兼容性。

## 安装与升级

发布 APK（如果存在）位于 `deliverables/`。安装前请先在应用内导出完整加密备份。

应用显示名为“拾日”，包名和签名身份保持 `com.hubra.app`，因此设计上支持同签名版本覆盖升级。升级前仍应先备份；真实设备上的覆盖安装和数据保留需要单独验收，不能由 JVM 测试替代。

## API 配置

在“设置 → AI 与记账规则”中新增或编辑 API 配置：

1. 填写配置名称、HTTPS Base URL、文本模型和图片模型。
2. API Key 只保存在本机 Keystore 加密存储中，不写入普通状态 JSON、备份或源码。
3. 可分别选择对话、图片/课表和饮食/日报使用的配置。
4. 保存后可执行能力检测；应用不会在请求失败时静默切换到其他服务商。

Base URL 必须是 HTTPS，应用会按 OpenAI-compatible Chat Completions 规则补齐 `/chat/completions`。当前源码没有硬编码 DeepSeek 地址或 API Key；首次状态中的示例配置是可编辑的 OpenAI-compatible 配置，用户应在首次使用前自行填写可信服务地址和密钥。

不要把 `signing.properties`、`.jks`、数据库、日志、备份或 API Key 提交到仓库。

## 提醒与后台行为

提醒由本地 AlarmManager 负责，AI 请求不在提醒投递链路中。计划和原定触发时间会持久化，应用启动、数据变化、重启、应用更新、系统时间/时区变化以及精确提醒权限变化时会重新安排。

支持的语义如下：

- 前台、最小化、应用回到后台但进程仍存活：由系统闹钟触发本地提醒。
- 应用重启后：从持久化计划恢复，并检查当日仍有效的过期提醒。
- 编辑、取消或完成任务后：旧计划会被校验并移除；完成通知只取消对应任务的通知，不清空其他任务。
- 系统从睡眠恢复后：是否及时唤醒由 Android、电池策略和厂商后台限制共同决定。
- 关闭通知权限、关闭通知频道、勿扰模式、强制停止或关机：应用无法保证用户看到通知。设置页的“提醒状态”只报告已安排、已接收和已提交系统通知，不把“提交成功”冒充为“用户已看到”。

通知完成操作使用任务 ID、日期和版本号校验；重复点击、任务已删除、任务已完成或任务已修改时不会重复写入。

## 开发者构建

先安装 JDK 17、Android SDK 35 和必要的 Android SDK Build Tools，然后在项目根目录执行：

```bash
# JVM 单元测试
./gradlew :core:test :app:test

# Debug APK
./gradlew :app:assembleDebug

# lint
./gradlew :app:lintDebug

# Android 仪器测试（需连接设备或可用模拟器）
./gradlew :app:connectedDebugAndroidTest
```

Windows 可使用 `gradlew.bat` 替代 `./gradlew`。构建签名配置通过根目录 `signing.properties` 读取；没有该文件时仍可构建未签名/默认 debug 变体。不要在 CI 或日志中输出签名密码。

## 项目结构

```text
core/                         可独立运行的领域模型、迁移和 JVM 测试
app/src/main/java/.../data    Room、状态仓库、备份和密钥存储
app/src/main/java/.../system  AlarmManager、通知、重排和后台 Worker
app/src/main/java/.../ai      API 协议、请求取消、结构化操作和日报
app/src/main/java/.../ui      Jetpack Compose 界面与交互
app/src/androidTest           设备级生命周期与媒体/备份测试
docs/                         架构与验证记录
deliverables/                 已生成的 APK、校验和及测试摘要（不放密钥）
```

系统提醒的关键路径是：

```text
任务/课程状态 → ReminderPlan → ReminderReschedule → AlarmManager
    → ReminderReceiver → 通知提交 → ReminderJournal 诊断记录
```

## 常见问题

### 为什么提醒没有横幅？

检查系统通知权限、`hubra-reminders` 通知频道、锁屏显示、勿扰模式、电池优化和精确提醒权限。设置页中的提醒状态可以区分计划、接收和提交失败。

### 为什么关闭精确提醒后会延迟？

系统会降级到 `setAndAllowWhileIdle` 等非精确机制。Android 和设备厂商可能延迟后台任务，应用不宣称百分之百准时。

### 为什么 API 请求失败后没有自动换服务商？

这是刻意设计：每个用途绑定明确配置，避免把数据发送到用户未选择的服务商。请检查 Base URL、模型、API Key、网络和服务额度。

### 为什么不能直接修改备份文件？

备份包含认证和版本化状态。请使用应用内恢复流程；恢复前会先校验并保留本机快照，错误口令或损坏文件不会覆盖当前数据。
