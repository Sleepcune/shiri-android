# 实现结构

## 本地业务

`core` 为可在 JVM 上独立测试的业务层：稳定 ID、金额分、日期/周次/课程实例、待办实例、版本检查、事务转移和依赖安全撤销。`DomainEngine.apply` 返回新状态和真实操作结果；失败不改变状态，同一操作 ID 重试返回已保存结果。

`app` 负责安卓 UI、Room、DataStore、Keystore、网络、OCR、通知和 Glance。Room 当前用一个版本化 `AppState` JSON 聚合行，保证转账、多项导入和撤销在同一数据库事务提交。提交成功后才发布 StateFlow。该结构适合当前个人规模；未来大规模数据可迁移为独立表，禁止破坏现有 ID 和操作记录。数据库没有破坏式迁移策略。

账务包含 expense/income/transfer/refund/adjustment，不把校园卡充值计为消费。未初始化账户保持未知。核账保留截止时刻；历史事实变动标记快照过时。课程分为课程、周次集合规则和单次例外；第 3、5–10 周展开集合，待补全课程不发送确定课前提醒。重复待办保存实例完成记录。

学期为独立 `Semester`，课程保存 `semesterId`，规则及例外通过课程继承归属。`Settings.activeSemesterId` 指定当前学期，起点/周数投影为该学期配置；节次时间共享。新建学期不复制旧课程，跨学期同名课程及原始导入 ID 重映射，切换保留旧资料。旧版本单学期状态由现有起点/周数迁移为默认学期。全局课程关联待办按原规则所属学期计算实际时间，AI 执行计划保存预期学期，避免重试后写入另一个学期。

## AI 边界

应用只允许 `ApiProtocol.allowedKinds` 的结构化业务请求。模型不能执行 SQL、命令或任意文件操作。图片与 OCR 作为资料，模式过滤阻止图片导入触发其他模块写操作。类型、日期、整数金额、目标和版本由业务程序校验；余额、课表与待办查询来自本地程序。

一次消息的操作计划在首次执行前保存，操作 ID 为消息 ID 加顺序号。重试复用计划和版本，避免部分成功后重复创建；旧备份或损坏情况下，已有执行记录但缺失计划的消息不能重新规划。多动作分别报告真实结果，不掩盖部分失败。失败输入保留为待处理，可恢复执行或手动处理。

默认兼容 Chat Completions；能力检测分别测试文字、图片、JSON 和工具调用。每个用途选定配置，不自动跨服务商发送。密钥由 Keystore AES-GCM 加密；后台可使用，备份不导出密钥。照片纠正方向并重编码移除原始元数据；API 输入只包含相关上下文，饮食分析才加入健康资料。

## 系统调度

AlarmManager 负责本地课程/待办/晚间核账，WorkManager 负责 AI 日报、每日快照与组件刷新。缺精确权限时降为允许空闲时触发的非精确提醒；组件边界使用可延迟普通 RTC 闹钟。重启、时间变更、数据变更和权限变化重排。

晚间通知先提交系统，再保存截至触发时间的源快照并排入有限重试 AI 工作。后台通知是否被用户看到无法确认，状态只称“已提交系统通知”。强制停止/关机不能保证投递，状态页显示是否缺触发记录。组件数据变化触发唯一刷新工作，不每分钟请求网络。

## 备份

AES-256-GCM + PBKDF2-SHA256 210000 次，随机盐和 IV，认证格式头。压缩包含版本化状态、受控附件路径、执行计划、日报源快照，限制总展开量 128 MB。先解密校验再恢复，错误口令不改现有数据库；恢复前另存本机快照，新图片名称避免覆盖现有图片。辅助文件替换失败时回滚。正式数据库替换后重新安排提醒/组件，便携恢复要求重新填 API Key。

健康分析按记录完整性给定性建议。提示词包含国家卫健委食养指南与 NHS 健康增重资料的链接；没有份量不编造热量或嘌呤数值，不把尿酸偏高视为确诊痛风，也不套用减脂目标。

## 0.2 数据与界面

`AppState.schemaVersion` 升至 2；Room 聚合表结构不变，读取旧状态后执行 `StateMigration.toV2` 并提交迁移结果。旧图片从实际引用推断用途，不能确定导入时间的旧图片从整理时间起算，旧消息补充请求关联。版本 1 完整备份可读取后迁移，版本 2 删除图片仅保留状态标记，不要求缺失文件。旧设置操作撤销遇到结构差异时保守报告冲突，不覆盖新设置。

导航使用可保存的主页面与返回栈，详情／设置使用进入前页面状态。业务页面独立于根协调器；变更摘要统一读取 `OperationRecord` 前后快照。`LedgerQueries` 接收账户、日期、分类及搜索条件，所有金额使用整数分，关联退款继承原消费分类，但统计使用退款实际日期和账户。

课表主体为横向周分页、固定星期栏与纵向课程区；重叠课程按传递重叠分组显示。学期外观持久保存在 settings 映射中，新增学期继承外观而不复制课程，节次继续共享。

## 对话执行与取消

完整、明确要求修改的放假通知可由本地解析生成一个 `course.calendar.adjust`。整条无法完整匹配、包含其他业务或否定意图时回到 AI 解析，不能先执行部分日期。整天调整按原始重复规则计算并 upsert 单次例外；`course.day.copy` 只添加目标周规则，保留源日与后续单次修改。日期与源／目标课程由本地业务校验，历史补课不因已经过去而擅自跳过。

每次失败尝试保留审计；继续处理生成失败动作的重试 ID，成功动作族直接复用结果，已撤销动作不会自动复活。结果分别报告成功、冲突和需补充，餐食文字列表先归一化，字段错误指出中文字段名。

清除对话在独立任务中完成，不受聊天忙碌状态拦截。请求注册表负责取消，数据库事务同时检查输入仍为待处理以及恢复代次，防止迟到操作或消息写入。短持锁事务与内存发布不可中断，网络及长任务可取消；OkHttp 取消覆盖完整响应体和 SSE，而非只等待响应头。

## 图片与备份协调

`MediaAccess` 序列化短文件操作；网络请求使用可取消的图片租约，避免传输时删图。照片重编码后按内容哈希去重，分类以用途和业务关联元数据维护，文件继续存于私有 attachments 目录。删除先持久记录 pending，再解绑文件，成功后提交删除标记，失败可重试。自动清理默认关闭，排除收藏、课表关联／背景、待处理请求和使用中图片。

备份、删除、恢复及源快照写入使用共享锁，辅助文件以临时文件原子替换。恢复先取消并等待旧请求释放租约，再取得文件锁；数据库恢复增加代次，日报写回也校验代次和源数据。恢复前快照仍按七份保留，因此历史备份可能包含已经删除的图片或聊天。API 密钥始终不在普通完整备份和源码中。

## 0.2 提醒恢复

提醒日志持久保存完整计划与原定触发时间。数据重排保留当日仍有效但刚到点的旧计划，近期补触发使用当前时间加一秒，去重仍使用原定时间；课前提醒只保留到该次课结束，不跨日批量补发。调课后的稳定课程 ID 可能仍含原日期，验证与通知内容必须从触发时间推导实际日期，而非解析 ID。

通知提交与日志使用短临界区；日报快照文件写入在临界区外限时执行，避免阻塞其他提醒。恢复权限、应用回到前台、重启与时钟变更重新检查计划。诊断区分安排成功、收到闹钟、权限阻止与提交系统通知，不声称用户已经看到。
